A data-modeling lab on a real 3-node cluster: query-first schema, day-bucketed partitions, TTL with TimeWindowCompactionStrategy, a counter table, consistency-level trade-offs and a node-stop recovery run.

What the real 3-node run printed

      
== all 3 nodes up ==
  WRITE SUCCEEDED at ALL, at QUORUM
== 1 of 3 nodes down ==
  WRITE FAILED at ALL
     Unavailable: Cannot achieve consistency level ALL
     (required_replicas=3, alive_replicas=2)
  WRITE SUCCEEDED at QUORUM  needs 2 of 3, has 2
  WRITE SUCCEEDED at ONE
== all 3 nodes back up ==
  recovered: WRITE SUCCEEDED at ALL

      
From the repo README. ALL fails at once with Unavailable, not a timeout, because the coordinator already knew from gossip it could not reach 3 replicas.

The three nodes share a host with no network latency between them, so QUORUM and ALL barely separate. The README says the real gap would show up across availability zones or regions, and that this lab does not show it.






  
Two real incidents

  

    
Two nodes joining at once collided on a token
Bootstrap Token collision between
/172.22.0.3:7000 and /172.22.0.4:7000
Fix: start one node, wait for UN in nodetool status, then start the next.

    
Writing right after DDL failed
WriteFailure: INCOMPATIBLE_SCHEMA from /172.22.0.3:7000
Schema changes spread by gossip. Writing before every replica agrees can hit one on the old schema. Fix: a short wait after creating tables.

Run it yourself

  
Docker and Python 3.12. Start the nodes one at a time.

  

    


docker compose up -d cassandra-1
# wait for UN in nodetool status
docker compose up -d cassandra-2
# wait for UN again
docker compose up -d cassandra-3

    

    


python -m pytest tests/ -v
python scripts/failure_recovery_demo.py
python -m cassandra_ops_lab.loadtest.load_runner \
  --n-events 300 --consistency LOCAL_QUORUM

    

  






  
What this does not do
    
    
  • It is a local lab with heap-capped containers. It makes no production capacity claim.
    • 
    
  • The replica arithmetic panel is a model of the rule, not Cassandra. The tests and the node-stop transcript are the evidence.
    • 
    
  • The README says Cassandra was a hands-on gap before this project. Treat it as a learning lab, not years of operating a cluster.
    • 
    
  • Counter tables cannot have a TTL and cannot hold non-counter columns. The tests cover that limit.
